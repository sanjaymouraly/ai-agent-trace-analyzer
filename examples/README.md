# Example traces

The JSON fixtures in `traces/` are deterministic, synthetic, safe-to-share
demonstrations. They are generated by `python -m examples.generate` and are
consumed by the import pipeline as ordinary JSON — the same way a real trace
would be. Startup seeds the same eleven runs idempotently.

| Run | Designed signal | What it demonstrates |
|---|---|---|
| `demo-orders-reference` | Successful multi-step path | The reference trajectory for the weekly order summary task |
| `demo-orders-invalid-args` | Invalid tool arguments → downstream missing data → rejected answer | Compare with the reference run; the counterfactual sandbox can be pointed at `bad-q1` with a corrected `orders` fixture |
| `demo-timeout-recovered` | Timed-out attempt followed by a successful retry | A timeout is observed, but it is **not** the root cause of a failed run — the run succeeds |
| `demo-rag-stale-context` | Explicitly irrelevant / superseded retrieval context | Retrieval-context signal plus the final evaluation error |
| `demo-wrong-tool` | The expected-tool annotation differs from the selected tool | An *inferred* hypothesis: the annotation itself may be wrong |
| `demo-corrupt-state` | Producer/consumer state version mismatch | An explicit state-validity flag and the dependent failure |
| `demo-delegation-timeout` | Multi-agent delegation with a timed-out specialist | Inspect the downstream merge impact |
| `demo-parallel-success` | Concurrent supplier, demand and inventory tools | Explicit fan-in dependencies; the critical-path estimate |
| `demo-final-answer-failure` | The tool succeeds but the evaluation rejects the answer | Why a successful tool response is not evidence of a correct answer |
| `demo-permission-denied` | Environment / permission failure | The auth/permission category plus the missing downstream data |
| `demo-ambiguous` | The run fails with no explicit failing span | The rule engine **abstains** instead of inventing a cause |

## Regenerating

```bash
python -m examples.generate
```

The generator is deterministic: the same run ids, span ids, timestamps and
values every time.

## Ground truth

The expected categories and the designed intervention points are recorded in
[`../evals/ground_truth.json`](../evals/ground_truth.json). The evaluation
harness measures the engine against them:

```bash
python -m evals.benchmark
```

These fixtures carry clean, deliberate annotations. They are a **regression
benchmark, not a representative sample of production instrumentation noise**,
and the measured numbers must not be presented as a real-world accuracy claim.
